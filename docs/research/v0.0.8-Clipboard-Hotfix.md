# v0.0.8 Clipboard Hotfix

## Problem

Windows 설치 앱에서 의미 텍스트 범위를 드래그한 뒤 `Ctrl+C`를 눌러도
클립보드가 갱신되지 않아, 이전에 남아 있던 문서 파일 경로가 메모장에
붙여넣어지는 사례가 확인되었다.

## Ownership

Lens interaction integration bug. rhwp의 semantic selection 및
`copySelection()` 결과는 실제 문서와 synthetic fixture에서 정상 문장을
반환했다. 문제는 WebView2 환경에서 브라우저 `copy` 이벤트만을 복사
진입점으로 사용한 UI 경로였다.

## Fix

- pointer-up에서 interaction surface의 키보드 포커스를 다시 보장한다.
- 선택 범위가 있을 때 `Ctrl+C`/`Cmd+C`를 직접 처리한다.
- rhwp semantic clipboard 결과의 plain text를 시스템 Clipboard API에 쓴다.
- WebView clipboard 권한이 허용되지 않으면 일시적인 비가시 textarea와
  `execCommand("copy")`를 로컬 fallback으로 사용하고 즉시 제거한다.
- 기존 `copy` 이벤트 경로는 context-menu/브라우저 호환 경로로 유지한다.

## Regression

- 기존 클립보드 값을 `.hwpx` 경로로 채운다.
- native `copy` 이벤트를 차단해 WebView 누락 상황을 재현한다.
- `Ctrl+C` 후 클립보드가 경로가 아닌 선택 의미 텍스트로 바뀌는지 검사한다.

이 패치는 clipboard delivery만 수정한다. Caption AutoNumber, character
selection geometry, SVG renderer, virtualization, caches 및 adapter 경계를
변경하지 않으며 Image/Table/Style Diff를 추가하지 않는다.
