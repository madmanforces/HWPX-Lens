# v0.0.9 Precision Selection and Review Ink Foundation

## Executive Summary

v0.0.9는 Image/Table/Style Diff를 추가하지 않고 문자 선택 정확도와 Review Ink 기반을
완성했다. v0.0.8의 native selection/clipboard 경로를 진단한 결과, rhwp 공개 API가
한글 문자 midpoint, 정확한 단어 범위, 여러 줄, 공백 및 표 셀 선택에 필요한 semantic
position과 geometry를 이미 제공했다. 따라서 정상 경로를 다시 작성하지 않고 자동
회귀 범위를 강화했다.

본문 Diff에는 UTF-16 호환 character alignment를 추가했다. 실제 변경 범위만
Original/Modified의 renderer-independent geometry로 변환하며, 추가 텍스트는 Modified,
삭제 텍스트는 Original에만 표시한다. 공백 삽입/삭제는 first-class segment로 보존하고
공백이 없는 쪽의 정확한 두 문자 경계 아래에 vector open-top marker를 표시한다.

Review Ink는 원본 SVG를 변경하지 않는 별도 overlay이고 pointer event를 받지 않는다.
active change는 강하게, inactive change는 약하게 보이며 mounted page에만 DOM을 만든다.
SVG는 Default, Canvas2D는 Experimental을 유지한다.

판정: **Precision Selection Accepted / Review Ink Foundation Accepted / Manual Visual
Validation Required**.

## Precision Selection Diagnosis

현재 SVG 기본 경로는 browser SVG DOM selection을 semantic identity로 사용하지 않는다.

```text
pointer document coordinate
→ RhwpNativeInteractionAdapter.hitTest()
→ section / paragraph / UTF-16 character offset
→ NativeSelection
→ getSelectionRects()
→ selection overlay / semantic clipboard
```

rhwp 공개 API의 실제 character caret boundary를 사용한다. 직접 glyph width를 추정하거나
SVG text node를 Lens identity로 쓰지 않는다. 자동 검증은 다음을 포함한다.

- `전원을` 각 한글 문자의 midpoint 전/후 offset
- 한 글자만 선택하고 동일 한 글자만 copy
- 정확한 단어 `전원을`
- visual line을 넘는 plain-text copy
- 공백 character geometry
- 표 셀 내부 exact copy
- reverse drag 정규화와 selection clear 기존 E2E

진단 결과 production selection 알고리즘의 rewrite는 필요하지 않았다. v0.0.9는 이
공개 API 경로를 정밀 회귀 gate로 고정한다.

## Character Diff

`diffTextSegments()`는 code point 단위 LCS alignment를 수행하되 output range는 rhwp와
호환되는 UTF-16 half-open offset을 유지한다. surrogate pair를 분할하지 않으며 큰 문단은
bounded fallback을 사용한다.

예:

```text
Before: 전원을 끈다.
After:  전원을 차단한다.
```

강한 Review Ink 대상은 문단 전체가 아니라 Original `끈`, Modified `차단` 범위다.
줄바꿈된 범위는 rhwp가 반환한 모든 line fragment rect를 그대로 보존한다.

## Whitespace as First-Class Change

paragraph alignment용 normalized text와 exact visible text를 분리했다. alignment는 기존
안정성을 유지하고, alignment상 같은 문단이라도 exact text의 공백이 다르면 Change를
생성한다.

```text
Original: 글자글자
Modified: 글자 글자
```

공백 insertion segment는 Original의 semantic insertion boundary를 저장한다. geometry는
앞 문자의 right caret boundary와 뒤 문자의 left caret boundary, 두 실제 character rect를
사용한다. marker는 Unicode 문자 출력이 아니라 다음 3개 stroke다.

```text
left vertical → bottom horizontal → right vertical
```

반대 방향의 공백 삭제에서는 Modified 쪽이 missing-whitespace side가 된다. 여러 공백
변경, 구두점 인접, 줄바꿈 인접 case를 별도 fixture로 검증했다.

## Review Ink Architecture

```text
DiffAdapter
→ Lens Change + TextChangeSegment[]
→ ReviewInkModel
→ InteractionAdapter document geometry
→ ReviewInkGeometry
→ ReviewInkOverlay on mounted page
```

Lens Core는 rhwp, SVG DOM 또는 Canvas node를 알지 못한다. geometry materialization은
`LensDocument.interaction` 경계를 사용하며 SVG/Canvas2D가 같은 contract를 공유한다.

형광펜은 theme token을 사용한 반투명 rect이며 underline/stroke가 없다. active fill
opacity는 0.38, inactive는 0.15다. whitespace marker는 foreground stroke이고 active와
inactive 굵기/opacity가 다르다. 모든 overlay는 `pointer-events: none`이다.

## Added and Removed Text

- added paragraph/text: Modified side에만 highlight
- removed paragraph/text: Original side에만 highlight
- absent side에 가짜 문장을 삽입하지 않음
- paragraph height, page reflow, table/image/caption 위치를 변경하지 않음

## Virtualization and Performance

- 전체 semantic Review Ink model과 change mapping은 eager analysis에 포함
- overlay DOM은 실제 rendered/mounted page에만 생성
- page unmount 시 visual overlay도 release
- 5-page per-document LRU와 target-page priority 유지
- pointer move full-document traversal 추가 없음
- analysis cache identity를 Review Ink schema로 갱신

lazy rendering, virtualization 및 cache 구조의 회귀는 발견되지 않았다.

## Existing Architecture Preservation

- SVG Default 유지
- Canvas2D Experimental 유지
- CanvasKit Deferred 유지
- DocumentAdapter / RenderingAdapter / InteractionAdapter / DiffAdapter 경계 유지
- Lens Core에서 rhwp 직접 import 없음
- rhwp Studio private compare API 사용/복제 없음
- eager analysis / lazy rendering / virtualization / cache 유지

## Remaining Limitations

- unmounted page를 넘어가는 continuous drag UX는 별도 milestone
- 여러 표 셀을 가로지르는 clipboard serialization은 public API 범위상 미지원
- 형광펜 hand-drawn texture와 최종 색상은 제품 디자인 결정 전 보류
- whitespace removed의 다른 교정부호는 임의 결정하지 않음; 공백이 없는 결과 쪽에는
  동일 missing-whitespace open-top marker를 사용
- 실제 office PC의 DPI, WebView2, Notepad 및 완전 offline 재시작은 수동 확인 필요
