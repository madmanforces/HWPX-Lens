# HWPX Lens v0.1.0 Public Alpha Candidate Report

## Executive Summary

HWPX Lens v0.1.0 is a private First Public Alpha Candidate. The implementation keeps SVG as the default renderer, Canvas2D as experimental, and CanvasKit deferred. It preserves the local-only rhwp document engine boundary and adds a compact Review Workspace, a merged Structure Diff tree, public-API image snapshots and image changes, unified table/image Review Ink, and a detachable review window.

The automated, synthetic, and anonymous 301-page local-fixture gates pass. The general-document source and installer are prepared for staging in the private GitHub repository; repository visibility remains an explicit owner action. The final decision is:

**B. CONDITIONAL GO — Manual Validation Required**

The candidate is suitable for user validation, but it is not approved for public release. Representative office-PC, WMF/EMF internal-text, mixed Korean/Latin, installer, and visual Review Ink checks still require the user's local environment.

1. text embedded inside particular WMF/EMF resources;

The required ownership trace remains source resource → rhwp conversion/layout → raw SVG/Canvas2D → Lens SVG. These are manual candidate gates, not claimed fixes.

## Architecture

The existing `DocumentAdapter`, `RenderingAdapter`, `InteractionAdapter`, and `DiffAdapter` boundaries are preserved. `@rhwp/core` remains isolated inside `packages/hwpx-adapter`; Lens Core does not call rhwp directly. Image analysis uses public local APIs such as page-control layout, page-flow image operations, and source-image bytes. No rhwp Studio compare code or private Studio API is copied or imported.

The performance architecture remains eager semantic analysis plus lazy visual rendering, viewport virtualization, a five-page per-document LRU render cache, target-page priority rendering, and in-memory SHA-256 session cache reuse. Document contents are not uploaded or written to a persistent analysis cache.

## Workspace

The main screen was reduced to a compact product header, compact file controls, a Review Workspace, and two document viewers. The Review Workspace:

- contains Structure and Changes tabs;
- labels them `목차 구조` and `변경사항`, and page-aligns TOC navigation separately from change-range navigation;
- can be resized horizontally from 240 to 440 pixels;
- can collapse to a 42-pixel review tab;
- can detach without reparsing either document;
- keeps the document viewport dominant.

## Structure Diff

The merged tree is built from public outline navigation metadata and existing outline changes. Nodes show added, removed, modified, or unchanged state and aggregate the changes in their subtree. A node selects a scoped Changes list and navigates using its semantic anchor. Selecting a Change finds and selects the deepest corresponding structure node.

Original/Modified separate TOC toggles were not added because the merged tree met the candidate navigation goal with less state and less duplicated UI.

## Text and Spacing Review Ink

Text changes use translucent range rectangles behind/over the glyph area rather than an underline. Active changes are stronger than inactive changes. Added text is marked only on Modified and removed text only on Original.

Spacing follows the user-approved contract:

- space insertion: red check mark at the engine-provided character/caret boundary;
- space removal/join: red open-top `└─┘` geometry at the joined boundary.

Both marks are vector geometry, zoom-independent in document coordinates, and `pointer-events: none` so they do not block selection or clipboard behavior.

## Image Diff

The image snapshot contains section, paragraph, control, stable path/order key, page, document-space bounds, MIME type, encoded byte length, original-resource SHA-256, and a rendering-metadata fingerprint. Dynamic-programming alignment combines source identity with stable semantic/layout context and does not use a simple page/index identity alone.

Supported results are:

- `IMAGE_ADDED`;
- `IMAGE_REMOVED`;
- `IMAGE_CHANGED`.

The internal model distinguishes `binaryChanged` from `renderingChanged`. A different encoded hash is not reported as pixel-level proof of a visual difference. Pixel-normalized PNG/JPEG/WMF/EMF comparison is not implemented in this candidate because there is no reliable backend-neutral normalization surface. Consequently, changed-region confidence is not invented: the current Review Ink uses a dotted outline around the actual image object bounds. Fine-grained changed-region masks remain a post-alpha capability.

Captions continue through ordinary semantic text diff and highlighter geometry. A reliable public caption-to-image relationship is not yet used as image identity.

## Table Diff

Tables are aligned by dimensions, merged-cell structure, and normalized cell content. Cell identity uses logical row/column and row/column spans. Basic cell text changes produce cell anchors; added/removed tables have contextual neighbors. When structure fingerprints differ, one table-structure change is emitted rather than false cell precision.

The current table ink gives the changed cell a light fill. Character-level strong ink inside a cell is not claimed for multi-paragraph cells because the stable cross-paragraph selection contract is not yet carried in `TableCellAnchor`. Table captions are still ordinary semantic text changes. Both items must be judged during manual validation and are known alpha limitations rather than hidden precision.

## Unified Review Ink

Review Ink is renderer-neutral: semantic Change → ReviewInkModel → document geometry → overlay. It does not mutate SVG content, reflow pages, or insert deleted content into the opposite document. Theme tokens control colors. Image outlines do not fill the image, and all default ink ignores pointer input.

## Detachable Workspace

The desktop path uses a Tauri `WebviewWindow` named `review-workspace`. Only serializable review state and actions are exchanged: selected Change, active structure node, filters, scope, and counts. HWPX bytes and rhwp document sessions remain in the main window. Closing the detached window returns the workspace to the main layout.

A browser-window fallback enables deterministic E2E coverage. Window size/last-monitor persistence is not implemented in v0.1.0; no sensitive document state is stored as a preference.

## Offline, Security, and Privacy

The production bundle contains only local application assets and one bundled rhwp WASM binary. It uses no CDN, remote JavaScript/CSS/font, cloud API, analytics, telemetry, upload, or login. The repository audit checked tracked paths and Git history for HWP/HWPX, installers, private fixture directories, internal notes, credentials, private keys, and absolute user paths. No blocker was found.

The GitHub repository was independently confirmed `PRIVATE`. It was not changed to Public and no Public Release was created.

## Known Limitations

1. WMF/EMF internal text and the reported mixed Korean/Latin run require the user's exact field fixtures.
2. Image visual comparison does not yet distinguish re-encoded-but-visually-identical resources through normalized raster pixels.
3. Image dotted ink outlines the whole changed image object; it does not claim a fine-grained pixel difference region.
4. Multi-paragraph table cells receive cell-level ink, not guaranteed character-level strong ink.
5. Detached window position, size, and last-monitor persistence are not stored.
6. The installer is not code-signed.
7. Office Baseline performance is not inferred from the development PC.

## Manual Validation Required

The companion `Manual Validation Required.txt` is mandatory before any public transition. It specifies pages 2, 3, 14, 15, and the reported mixed-run page 283 on the anonymous 301-page local fixture, plus exact synthetic text/spacing/table/image pairs and detached-window/offline checks.

## Public Alpha Readiness

**Final decision: B. CONDITIONAL GO — Manual Validation Required.**

The code and private installer candidate meet the automated technical gate, but user validation is still required for representative HWPX fidelity, proofreading symbols, image/table ink usefulness, an actual second monitor, an office-baseline PC, offline startup, and Windows installation. A public repository transition or Public GitHub Release is explicitly not authorized by this result.
