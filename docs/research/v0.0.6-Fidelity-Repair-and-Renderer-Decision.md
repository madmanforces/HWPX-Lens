# v0.0.6 Fidelity Repair and Renderer Decision

## Executive Summary

v0.0.6은 실제 301쪽 로컬 문서에서 재현된 F-001, F-002, F-003, F-005를
하나의 Lens integration root cause로 수정했다. rhwp는 페이지마다
`body-clip-*`, `cell-clip-*` 같은 SVG ID를 재사용하지만, 여러 페이지와 두 문서를
같은 HTML document에 mount하면 `url(#...)`가 다른 페이지의 같은 ID를 참조할 수
있었다. 그 결과 텍스트, 표, 제목, WMF 변환 그림이 서로 무관한 clip 영역에 의해
잘리거나 전부 사라졌다.

`RhwpDocumentSession`의 문서 instance와 page index를 조합한 namespace로 모든 SVG
ID와 local fragment reference를 일관되게 다시 작성했다. 수정 후 raw SVG,
standalone sanitized SVG, Lens SVG, Canvas2D를 페이지 2, 3, 12, 13, 14, 15에서
A/B했다. raw와 standalone sanitized PNG는 여섯 페이지 모두 SHA-256까지 같았고,
Lens SVG는 이전에 깨졌던 박스 본문, 표, 제목, WMF 그림을 완전하게 표시했다.

F-004 캡션 자동번호는 미해결이다. 원본 HWPX에 자동번호 값이 존재하지만 raw SVG와
Canvas2D가 모두 마지막 숫자를 생략한다. 이는 rhwp shared parser/layout/control
issue로 분류했으며 Lens에서 숫자를 추측해 삽입하지 않았다.

Renderer 결정은 **Option B — SVG Default / Canvas2D Experimental**이다. 이번 결함은
SVG backend 자체가 아니라 Lens에 여러 SVG를 동시에 mount한 integration 결함이었고,
수정 후 SVG가 known pages를 통과한다. Canvas2D로 전환해도 F-004는 해결되지 않는다.

## F-001 Root Cause / Fix

### Root cause

**Ownership: A. Lens integration bug**

raw rhwp SVG와 standalone sanitized SVG에서는 왼쪽 glyph가 정상이다. 동일 페이지를
Lens에 mount한 경우에만 글자가 잘렸다. 페이지별로 반복되는 clipPath ID가 containing
HTML document 안에서 충돌하여, glyph가 자기 cell/textbox가 아닌 다른 SVG의 clip을
사용했다.

문제는 glyph bearing, paragraph x, margin 또는 CSS padding이 아니었다. 따라서 여백을
늘리는 보정은 추가하지 않았다.

### Fix

- 각 `RhwpDocumentSession`에 고유 rendering namespace 부여
- namespace에 page index 포함
- SVG의 모든 `id` prefix 처리
- `url(#id)`, `href="#id"`, namespaced href, ARIA ID reference 동시 재작성
- 페이지 안에서 모든 local fragment reference가 자기 SVG에 존재하는지 자동 검사

### Result

Page 2와 14에서 박스 각 줄의 첫 글자와 전체 본문이 복구됐다. SVG와 Canvas2D 모두
같은 내용을 표시한다.

## F-002 Root Cause / Fix

### Root cause

**Ownership: A. Lens integration bug**

원본 내용은 semantic snapshot, raw SVG, standalone sanitized SVG에 존재했다. Lens에
mount했을 때만 boxed table이 다른 페이지의 cell clip을 참조하여 본문 전체가 clip됐다.
child paragraph, page assignment 또는 renderer tree 누락이 아니었다.

### Fix and result

F-001과 같은 page-local SVG ID isolation으로 Page 3의 박스 내부 전체 내용이 복구됐다.

## F-003 Root Cause / Fix

### Root cause

**Ownership: A. Lens integration bug**

문제 그림은 HWPX package의 WMF resource이며 rhwp가 SVG image payload로 변환한다.
raw SVG와 Canvas2D는 그림 전체를 표시했다. Lens SVG에서 outer page/control clip
reference가 다른 페이지의 동명 ID로 resolve되어 넓은 그림 영역이 사라지고 작은
조각만 남았다. WMF source bounds 또는 conversion 자체의 실패가 아니었다.

### Fix and result

page-local fragment ID isolation 후 Page 15에서 왼쪽 입체도, 오른쪽 정면도, 원형 번호,
그림 아래 표의 전체 행이 복구됐다. embedded SVG payload를 조작하거나 screenshot
fallback을 사용하지 않았다.

## F-004 Root Cause / Fix

### Root cause

**Ownership: F. rhwp shared layout / control issue**

원본 caption paragraph는 다음 의미 구조를 가진다.

```text
caption text → autoNum(num=3, PICTURE/TABLE) → punctuation → caption text
```

HWPX parser는 autoNum을 control과 한 글자 placeholder로 보존한다. 그러나 caption
layout의 `apply_auto_numbers_to_composed()`는 run에서 literal two-space pattern만 찾아
번호를 삽입한다. autoNum placeholder가 punctuation 바로 앞에 있는 caption에는 두
공백이 없으므로 치환이 실행되지 않는다.

### Result

- Expected: `그림 2-3.`, `표 2-3.`
- Actual in raw SVG: `그림 2-.`, `표 2-.`
- Actual in Canvas2D: 동일
- Actual in Lens SVG: 동일

Lens가 번호를 추측하지 않는다. ignored upstream candidate
`prCandidates/rhwp/2026-09-03-caption-autonum-placeholder-not-rendered.md`에 위치 기반
치환 제안과 regression test를 기록했다. 외부 Issue/PR은 생성하지 않았다.

## F-005 Root Cause / Fix

### Root cause

**Ownership: A. Lens integration bug**

박스 제목은 semantic model과 raw SVG에 존재했다. Lens에 mount한 페이지에서만 같은
ID를 가진 다른 clipPath에 의해 제목 영역이 사라졌다.

### Fix and result

page-local ID isolation 후 Page 14의 박스 제목들이 다시 표시된다.

## Default Renderer Decision

**Option B — SVG Default / Canvas2D Experimental**

근거:

1. SVG raw output은 known visual objects를 이미 올바르게 포함했다.
2. Lens의 document/page ID namespace로 실제 integration failure가 제거됐다.
3. Canvas2D로 전환해도 shared caption-number issue는 남는다.
4. 기존 SVG production path, virtualization, cache, navigation을 불필요하게 migration할
   이유가 없다.
5. Canvas2D는 독립 A/B 진단 backend로 계속 가치가 있다.

Automatic per-document 또는 hybrid per-page 선택은 채택하지 않는다. 현재는 안정적인
preflight 기준이 없고 복잡성만 증가한다.

## Performance Regression

기존 eager analysis, lazy rendering, viewport virtualization, 5-page LRU,
target-page priority, SHA-256 session cache 구조는 변경하지 않았다.

301-page local benchmark:

| Metric | Result |
|---|---:|
| Open Original | 803 ms |
| Open Modified | 680 ms |
| Snapshot Original | 90 ms |
| Snapshot Modified | 55 ms |
| One-change diff | 19 ms |
| Both-side mapping | 20 ms |
| All page metadata | 2 ms |
| Four raw SVG pages | 2,433 ms total |
| Process RSS | 143 MiB → 632 MiB |
| Heap used | 29 MiB → 337 MiB |

이 수치는 개발 환경 진단이며 사무용 물리 PC 기준을 대체하지 않는다. E2E의 eager
analysis/lazy rendering/cache와 change navigation test는 통과했다. ID rewriting은 현재
요청된 virtualized page에만 적용되어 전체 301쪽을 선렌더하지 않는다.
