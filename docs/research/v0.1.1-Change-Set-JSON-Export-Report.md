# v0.1.1 Change Set JSON Export Report

## Executive Summary

HWPX Lens `0.1.1`은 화면의 Review Ink와 동일한 canonical `Change[]`를 범용 Change Set JSON으로 저장한다. Original은 `previous`, Modified는 `latest`로 고정되며, 두 raw HWPX SHA-256을 이용한 deterministic `comparisonId`, 의미 Anchor, 변경 전후 text/normalized text/fingerprint, character segment, type-specific table/image metadata와 변경 없는 항목까지 포함한 전체 목차 대응표를 제공한다.

JSON은 저장 전에 raw bytes, ID/참조, summary, Anchor/range, 지문, 목차 coverage/path/scope와 payload safety를 재검증한다. Draft 2020-12 Schema와 positive/negative contract test, 반복 export 결정성 test, 브라우저 E2E 및 native save adapter test를 추가했다. 기존 renderer, Diff, Review Ink, navigation, virtualization, session cache와 offline 경계는 변경하지 않았다.

자동 Acceptance Gate 1–8 결과는 **GO**다. 후속 사용자 승인에 따라 Git-ignored 영역에 비공개 로컬 수동 검증용 NSIS 설치본을 생성했다. 실제 설치 앱에서의 저장 대화상자·대표 문서 육안 대조와 office PC 검증은 별도 Manual Validation으로 `PENDING`이다. commit, tag, GitHub push, release 또는 publication은 수행하지 않았다.

## User Flow

1. 사용자가 `ORIGINAL`에 이전 문서, `MODIFIED`에 최신 문서를 연다.
2. 기존 eager analysis와 change mapping이 완료되면 `Change Set JSON 내보내기`가 활성화된다.
3. 파일명, 변경 전후 텍스트, 목차 경로, 위치·지문이 민감할 수 있고 원본 이미지 binary는 포함되지 않는다는 경고를 확인한다.
4. export 시작 시 현재 File, snapshots와 canonical changes 참조를 하나의 일관성 경계로 캡처한다.
5. immutable browser File을 다시 읽어 raw SHA-256/byteLength를 계산하고 DTO를 만든다.
6. semantic/reference integrity validation과 JSON safety validation을 통과한 뒤에만 `.json` 저장 대화상자를 연다.
7. 취소는 비교 상태를 보존하고, hash/검증/직렬화/쓰기 실패는 성공으로 표시하지 않는다.

Tauri production 경로는 dialog와 text-file write plugin을 사용한다. browser development 경로는 로컬 Blob download만 사용한다. 둘 다 외부 전송이 없다.

## Canonical Change Model Reuse

Export는 `DiffAdapter.compare()`가 이미 생성하고 Review Ink가 소비하는 `Change[]`를 입력으로 받는다. 별도 export diff engine을 만들지 않았다. 각 canonical change를 의미 위치로 안정 정렬한 뒤 `chg-000001` 형식의 ID를 부여한다. 기존 text segment, Anchor confidence와 table/image snapshot metadata를 그대로 type-specific DTO로 투영한다.

이 설계 때문에 화면과 JSON의 변경 판정이 서로 다른 알고리즘으로 갈라지지 않는다. Export 계층은 비교를 재판정하지 않고 계약 변환, 전체 목차 관계 보강과 검증을 담당한다.

## Top-Level and Type-Specific Contract

최상위 serializer 순서는 다음으로 고정된다.

`schemaVersion`, `comparisonId`, `exportId`, `exportedAt`, `generator`, `analysis`, `coordinateSystem`, `fingerprintSpec`, `documents`, `summary`, `changes`, `outlineMappings`.

`changes`는 `text`, `outline`, `table`, `image`를 지원한다.

- text: content/whitespace detail과 UTF-16 half-open character segments.
- outline: renamed/added/removed/moved detail, level과 full path.
- table: structure/cell/add/remove, row/column/span과 table/cell fingerprints.
- image: add/remove/change, binary/rendering flags, classification, encoded source hash와 render fingerprint. Binary payload는 없음.

added는 original `null`, removed는 modified `null`, modified는 양쪽 필수다. 존재하는 side에는 applicable Anchor와 root부터 현재 항목까지 전체 outline path가 있다.

## Full Outline Mapping

`alignOutlineSnapshots()`의 기존 정렬 결과를 사용하여 모든 previous/latest outline을 각각 정확히 한 번 coverage한다. mapping ID는 안정 정렬 후 `map-000001` 형식으로 부여된다.

relations는 `unchanged`, `moved`, `renamed`, `modified`, `added`, `removed`이며 moved+modified 조합을 지원한다. added/removed/unchanged는 배타적이다. 제목·내용 지문, level, number와 parent path의 실제 equality만 evidence로 기록하며 matcher가 계산하지 않은 유사도 점수는 만들지 않는다. 완전한 equality가 실제 확인된 pair에만 `similarity: 1`을 기록한다. 중복 level/title 지문은 `approximate`로 낮춘다.

`relatedChangeIds`는 mapping scope에 실제로 포함된 change만 연결하며 validator가 누락과 범위 밖 참조를 모두 검사한다.

## comparisonId

두 입력 SHA는 ASCII whitespace를 trim하고 lowercase 64 hex로 검증한다. schemaVersion은 선행 `v`를 허용하지 않는 strict SemVer로 canonicalize한다. preimage는 BOM 없는 UTF-8, LF, 마지막 LF 없음이다.

```text
hwpx-lens-comparison-id-v1
originalSha256:<normalized original SHA-256>
modifiedSha256:<normalized modified SHA-256>
schemaVersion:<canonical schema version>
```

출력은 `cmp-` + SHA-256 lowercase hex 64자리다. 명세 known vector 결과 `cmp-15580855e4d1bbdd548eee06d533bc03149b11951d4098f8aa83f1422949867d`가 정확히 통과했다.

## JSON Schema

- Path: `schemas/change-set.schema.json`
- Draft: JSON Schema 2020-12
- Fixed schemaVersion: `1.0.0`

Schema는 top-level required, roles, hash/ID pattern, status/type/kind/detail/relation/segment enum, added/removed/modified side nullability, relation exclusivity, index/count/range/span/rect/similarity와 type-specific data 구조를 검증한다. 같은 1.x 소비자가 알 수 없는 미래 선택 필드를 무시할 수 있도록 object 확장은 허용하지만 required/type/enum/conditional contract는 유지한다.

Ajv `8.17.1`과 ajv-formats `3.0.1`은 Schema contract test 전용 dev dependency이며 둘 다 MIT다. runtime bundle에는 포함되지 않았다.

## Semantic and Reference Integrity

Schema 밖의 다음 invariant를 pure validator로 확인한다.

- document SHA와 byteLength를 실제 raw bytes로 재계산.
- comparisonId canonical 재계산과 Original/Modified role.
- analysis supported/completed/status consistency.
- change/mapping ID uniqueness와 related ID 존재·scope completeness.
- summary의 kind/type/relation 집계.
- change side nullability와 detail/kind consistency.
- Anchor index/range 및 snapshot 대상 존재, paragraph/cell fingerprint.
- text normalization과 content fingerprint.
- 모든 outline ID의 정확히 한 번 coverage와 full path.
- moved/renamed/unchanged relation 의미.
- table/cell 및 image source/render metadata.
- 함수, undefined, BigInt, NaN/Infinity, typed binary, Blob, data URL, local absolute path와 credential pattern 배제.

검증 오류에는 invariant 위치를 표시하지만 전체 문서 내용이나 절대경로를 출력하지 않는다.

## Deterministic Payload

동일 bytes/snapshots/changes/schemaVersion으로 독립 builder를 두 번 실행했다. parse 후 JSON Pointer `/exportId`와 `/exportedAt`만 정확한 sentinel 값으로 치환하고 다시 serializer를 적용한 결과가 byte-for-byte 동일했다.

허용 제외 목록은 위 두 pointer뿐이다. broad `*Id`/`*At` regex는 없다. 특히 `/comparisonId`는 치환·삭제·마스킹하지 않았고 두 payload에서 동일했으며 documents SHA와 schemaVersion으로 각각 재계산해 일치시켰다.

serializer 출력은 UTF-8 no BOM, 2-space indentation, LF와 final LF 하나다.

## Offline, Public Boundary and Privacy

`audit:offline`은 외부 asset 없이 bundled rhwp WASM 하나만 확인했다. export code에는 fetch, telemetry, upload, external API 또는 CDN이 없다.

`audit:public`과 `audit:ignored`가 public source/schema/docs/fixture에 private/local fixture/binary/domain-specific 내용이 없고 ignored local 작업 경로가 untracked임을 확인했다. Change Set은 범용 비교 사실만 제공하며 외부 프로그램의 업무 정책이나 자동 수정 결정을 실행하지 않는다.

Tauri에는 save dialog와 selected-path text write 기능만 추가했다. npm package license는 dialog/fs 모두 `MIT OR Apache-2.0`; Rust plugin도 동일 계열이다. production JS는 약 2.3 kB 증가했고 rhwp WASM 크기는 9,940.50 kB로 유지됐다.

`npm install`은 dependency graph에 moderate advisory 2개가 있다고 표시했다. 별도 `npm audit --omit=dev` 재확인은 npm audit endpoint network timeout으로 완료하지 못했다. 이 작업의 build/offline/public gate 실패는 아니지만 다음 release 점검에서 advisory 원인 package를 다시 조회해야 한다.

| Body paragraphs | 3,646 |

이 test는 large full-outline coverage, serialization, raw hash와 integrity를 검증하지만 same-file pair라 changes는 0개다. 변경이 많은 301쪽 pair와 office baseline PC의 UI responsiveness는 Manual Validation 대상이다.

전체 목차마다 full path를 반복 기록하므로 목차가 많은 문서는 JSON이 커진다. 계약 완전성을 위해 이번 버전에서는 생략하거나 압축 표현으로 바꾸지 않았다. 향후 측정 결과가 필요하면 schema 호환성을 유지하는 streaming writer 또는 선택적 dictionary를 별도 검토할 수 있다.

## Known Limits and Manual Work

- 정상 UI는 완료된 비교만 export한다. DTO/Schema는 partial/failed status와 warnings를 표현하지만 partial/failed UI fixture는 아직 없다.
- Windows x64 NSIS 로컬 검증본 생성과 비공개 프로필 검사는 PASS했다. 설치 및 native save dialog의 물리 PC 수동 실행은 아직 하지 않았다.
- 대표 previous/latest pair에서 JSON before/after, paths, segments와 화면의 육안 대조가 필요하다.
- moved+modified, renamed, added, removed와 ambiguous duplicate 사례를 포함한 실제 문서 수동 검증이 필요하다.
- large changed pair와 office PC 성능 확인이 필요하다.
- npm advisory endpoint가 응답하지 않아 moderate advisory 2개의 package별 재조회가 남았다.

수동 문서: `docs/research/v0.1.1-Change-Set-JSON-Export-Manual Validation Required.md`
