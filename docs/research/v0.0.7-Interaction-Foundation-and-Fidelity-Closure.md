# v0.0.7 Interaction Foundation and Fidelity Closure

## Executive Summary

v0.0.7은 새 Diff Type을 추가하지 않고 캡션 자동번호와 문서 interaction 기반을
완성했다. F-004는 `rhwp`의 caption layout이 literal 두 공백만 찾던 문제였다.
`hp:autoNum`의 semantic control position으로 placeholder를 찾고 raw model text 대신
`display_text`만 치환하는 local upstream patch를 검증·적용했다.

실제 301쪽 로컬 문서의 Page 15에서 raw SVG, Lens SVG, Canvas2D 모두
`그림 2-3.`과 실제 표 sequence인 `표 2-2.`를 표시하며, Page 16의 다음 번호도
`그림 2-4.`, `표 2-3.`으로 이어진다. Lens에서 번호를 추측하지 않는다.

기본 SVG renderer는 이제 browser SVG text selection이 아니라 공개 rhwp hit-test,
selection rect, clipboard API를 사용한다. 한글 문자 midpoint, 정확한 부분 문자열,
공백, 줄바꿈, 표 셀을 자동 검증했다. 문자 전후 caret 경계와 character rect를 함께
제공하는 renderer-neutral geometry contract를 추가하여 다음 milestone의 형광펜 및
공백 proofing marker가 text-width 추정 없이 실제 문서 좌표를 사용할 수 있게 했다.

판정은 **Known Fidelity Gate Passed / Interaction Foundation Accepted**이다.
SVG는 Default, Canvas2D는 Experimental을 유지한다. 최종 제품 사용 승인에는 아래
Manual Validation이 필요하다.

## F-004 Root Cause and Repair

### Root cause

Ownership: **rhwp shared layout/control issue**.

`apply_auto_numbers_to_composed()`는 AutoNumber control이 있음에도 각 run에서 literal
`"  "`만 찾았다. `caption text → autoNum → punctuation` 구조는 visible placeholder가
한 칸뿐이라 치환되지 않았다.

### Repair

- `auto_number_placeholder_positions()`로 control별 semantic 위치를 구함
- `assigned_number`, format, prefix, suffix 규칙 유지
- 뒤쪽 위치부터 `replace_composed_char_with_display()` 호출
- raw `run.text`, char offset, selection model axis 보존
- Picture와 Table 번호를 type별로 독립 처리

Lens business logic에 번호 계산이나 문자열 추측은 없다.

### Packaging

공개 npm package는 `@rhwp/core@0.8.6`을 유지한다. 패치된 WASM만
`vendor/rhwp-0.8.6-hwpx-lens/`에 임시로 둔다. 빌드 전 checksum과 rhwp version을
검증한 후 npm package의 ABI-compatible WASM을 준비한다. upstream release에 동일한
수정이 포함되면 override를 제거한다.

## Native Selection Architecture

흐름:

```text
pointer document coordinate
→ RhwpNativeInteractionAdapter.hitTest()
→ section / paragraph / character offset
→ semantic NativeSelection
→ getSelectionRects()
→ renderer-independent SVG overlay
```

Lens Core는 SVG node나 DOM selection을 identity로 사용하지 않는다. 기본 SVG와
Canvas2D가 같은 `NativeInteractionAdapter` contract를 공유한다.

rhwp 0.8.6의 public hit-test는 run별 character position과 midpoint를 사용한다.
`전원을`의 각 문자 경계 양쪽을 실제 좌표로 hit-test하여 midpoint 전에는 현재 offset,
후에는 다음 offset이 반환됨을 자동 검증했다.

## Clipboard

Ctrl+C는 browser SVG selection을 복사하지 않는다.

```text
NativeSelection
→ copySelection() / copySelectionInCell()
→ getClipboardText()
→ ClipboardEvent text/plain
```

검증 결과:

- exact substring `전원을` → 동일한 plain text
- 여러 visual line 범위 → 문자별 newline 없음
- reverse drag → 정방향 semantic range로 정규화
- table cell 문장 → cell public API로 복사
- default SVG와 Canvas2D E2E system clipboard → PASS

표 여러 셀을 가로지르는 serialization은 이번 범위가 아니다.

## Character and Whitespace Geometry

Lens Core에 다음 renderer-neutral contract를 추가했다.

- `LensTextPosition`
- `LensTextRange` (half-open)
- `TextBoundaryGeometry`
- `CharacterGeometry`
- `NativeInteractionAdapter.getCharacterGeometry()`

한 문자의 selection rect와 before/after caret 경계를 모두 반환한다. 공백도 동일한
semantic character로 다뤄진다. 다음 단계의 missing-whitespace `└─┘` marker는
before-character right boundary와 after-character left boundary를 사용하며 임의 폭을
계산할 필요가 없다.

## Pointer Performance

pointermove마다 full document traversal을 추가하지 않았다. 최신 document coordinate만
저장하고 animation frame당 한 번 public hit-test와 selection rect 조회를 수행한다.
pointerup에서는 pending frame을 취소하고 최종 좌표를 동기적으로 다시 계산한다.
따라서 고빈도 move event를 합치되 최종 선택 정확도는 유지한다.

## Virtualization and Renderer Independence

- mounted page의 interaction surface만 hit-test
- page mount/change navigation 후 같은 adapter 재사용
- document coordinate와 CSS/viewBox transform 분리
- overlay는 SVG/Canvas pixel/text node를 수정하지 않음
- 5-page LRU, lazy rendering, target-page priority 유지

Canvas2D는 동일 selection/copy contract E2E를 통과했지만 Default renderer 변경 근거는
없으므로 Experimental을 유지한다.
