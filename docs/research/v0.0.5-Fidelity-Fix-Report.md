# HWPX Lens v0.0.5 Fidelity Fix Report

## Executive Summary

HWPX Lens `0.0.5`는 301-page local fixture에서 확인된 표/박스 내부 글자 하단 clipping을 수정한다. Lens CSS나 SVG clipPath를 임의 보정하지 않고, 해당 표 행 높이 및 glyph 배치 수정이 포함된 공개 `@rhwp/core` 패치 릴리스 `0.8.6`으로 `0.8.4`에서 업데이트했다.

동일한 익명 local fixture를 두 버전으로 비교했을 때 영문·한글·숫자 glyph의 baseline이 셀 clip bottom을 넘는 의심치는 `1,190 → 0`이었다. 기존 Fidelity Gate의 더 넓은 문자 판정 기준에서는 27개 페이지, 1,305개 의심치였다. 새 엔진에서 페이지 수는 301로 유지됐고, 본문·표 셀 semantic coverage와 raw/sanitized SVG 문자 완전성도 유지됐다.

이 결과는 실제 rendering defect 한 종류가 root-cause 계층에서 수정됐음을 입증한다. 다만 WMF/EMF, 복잡한 캡션 번호, 모든 표 형태의 Hancom 원본 대비 pixel fidelity는 자동 검증만으로 합격 처리할 수 없다. 따라서 설치본은 사용자 수동 검증이 필요하며 Table/Image/Style Diff 기능 개발은 계속 중단한다.

## Root Cause

문제는 parser-level text loss나 Lens sanitizer가 아니었다. `@rhwp/core@0.8.4`가 실제 문서의 일부 고정 높이 표 셀에서 내용 행 높이를 약 `18.4` SVG unit으로 계산한 반면, 그 안의 16-unit 글자와 여백을 포함한 baseline은 cell clip bottom보다 최대 약 `4.05` unit 아래에 놓였다. 대표 셀에서는 약 `2.72` unit 초과했다.

같은 문서를 `@rhwp/core@0.8.6`으로 열면 해당 행 높이가 약 `31.1` unit으로 계산되고 glyph baseline이 clip 안에 들어왔다. 페이지 수와 semantic text는 변하지 않았다. 분류는 **shared table/line layout에서 유래해 SVG cell clipping으로 나타난 upstream engine defect**다.

이전 prompt의 “page 27” 표현은 한 개의 27쪽을 뜻하지 않았다. 실제 구버전 감사 결과는 301쪽 중 27개 페이지에서 의심치가 발견됐다는 의미다.

## Fixes Applied

- `@rhwp/core` exact pin을 `0.8.4`에서 `0.8.6`으로 업데이트
- 엔진 버전을 포함하는 analysis-cache identity를 `0.8.6`으로 갱신하여 구버전 layout snapshot의 stale reuse 방지
- 표/셀 baseline clipping 합성 회귀 fixture 및 검사 추가
- 실제 local fixture에서 문서 원문을 저장하지 않는 baseline/clip 진단 추가
- 본문, 표 셀, raw SVG, sanitized SVG를 함께 추적하는 Text Completeness Audit 추가
- table/image/caption synthetic fidelity corpus 확대

## Lens Fixes

Lens 자체의 CSS, page wrapper, sanitizer 또는 overlay를 변경하지 않았다. 검사 결과 raw SVG와 sanitized SVG의 의미 문자 차이는 0이고, 실제 문서 이미지 차단도 0이었기 때문이다. Lens 쪽 변경은 새 엔진을 정확히 pin하고 캐시 identity를 갱신한 integration 수정뿐이다.

`DocumentAdapter`, `RenderingAdapter`, `InteractionAdapter`, `DiffAdapter` 경계는 유지됐다. `@rhwp/core` import는 `hwpx-adapter`와 독립 test harness에만 있으며 Lens Core에는 추가되지 않았다.

## rhwp Local Patches

없음. 비공개 Studio API, 복제 코드, permanent fork, patch-package를 사용하지 않았다. 공개 MIT 패키지 `@rhwp/core@0.8.6`만 사용한다. 참고한 upstream 릴리스는 [rhwp v0.8.6](https://github.com/edwardkim/rhwp/releases/tag/v0.8.6)이다.

## Table Fidelity

의미 있는 표 셀 문단 `4,727`개가 모두 visual cell block에서 원문 내용을 유지했다. 구버전 local fixture의 1,190개 엄격 clip suspect는 새 버전에서 0이 됐다. 합성 6x5 tight-cell 회귀와 기존 단순/병합/cross-page table corpus도 통과했다.

이는 확인된 cell-text clipping 결함의 수정 증거다. 그러나 대표 문서의 모든 병합 구조, 표 페이지 분할, boxed-table 외형을 원본과 pixel 단위로 동일하다고 보장하지는 않는다.

## Image Fidelity

합성 PNG/JPEG 및 배치·크기·crop fixture는 resource 보존과 sanitizer non-blocking을 통과했다. 실제 fixture에서 public renderer가 사용한 source image는 93개이며 공개 API에서 73 PNG와 20 SVG resource로 관찰됐다.

이는 pipeline 전달을 증명할 뿐 원본 WMF/EMF의 선, 글자, bounds, aspect ratio까지 증명하지 않는다. WMF/EMF 원본 대비 visual validation은 계속 필요하다.

## Caption Status

실제 fixture layout에서 그림/표 번호 형태 token 245개가 관찰됐고 synthetic picture caption은 통과했다. Native table caption을 합성하는 공개 API gap과 실제 번호·object relationship의 pixel 검증은 남아 있다. Lens가 누락 번호를 추측해 삽입하지 않는다.

## SVG vs Canvas2D

SVG는 `0.0.5`의 default renderer이고 Canvas2D는 experimental 상태다. 두 adapter 모두 301페이지 인식, semantic mapping, selection/copy, change navigation smoke를 통과했다. Canvas2D E2E도 public API만으로 통과했다.

이번 clipping fix는 shared table layout의 새 엔진 계산으로 SVG에서 직접 검증됐다. Canvas2D의 실제 affected page pixel A/B는 설치판에서 selectable renderer로 노출하지 않았으므로 default 승격 근거로 사용하지 않는다.

## Performance Regression

18,057,009-byte / 301-page / 3,646-body-paragraph / 381-table local fixture에서 측정한 smoke 결과:

| Stage | Result |
|---|---:|
| Open Original | 733 ms |
| Open Modified | 543 ms |
| Snapshot Original | 72 ms |
| Snapshot Modified | 53 ms |
| Single-change diff | 26 ms |
| Map one change, both sides | 20 ms |
| Four SVG pages | 2,271 ms |

환경·warm state가 과거 측정과 완전히 같지 않아 절대값 비교는 하지 않았다. Eager semantic analysis, lazy visual rendering, viewport virtualization, LRU render cache, target-page priority와 ephemeral analysis cache 구조는 그대로 유지됐다. UI/E2E 성능 회귀는 발견되지 않았다.

## Remaining Known Issues

- 실제 WMF/EMF의 원본 대비 변환 fidelity는 미검증
- 복잡한 그림/표 caption 번호·위치의 원본 대비 검증 필요
- 일반 표 이외의 복잡한 병합·page split·floating control은 사용자 수동 검증 필요
- SVG text는 glyph 단위 DOM이므로 브라우저 native selection/copy 대신 rhwp semantic interaction을 계속 사용
- Canvas2D는 설치판의 default/선택 renderer가 아니며 pixel fidelity 판정은 보류

## Upstream PR Candidates

이번에 수정한 clipping은 공개 `0.8.6` 릴리스로 해결되어 별도 local patch나 새 외부 Issue/PR을 만들지 않았다. 기존에 기록한 caption fixture/API gap과 WMF/EMF source-format/fidelity metadata 후보는 `prCandidates/rhwp/`에 local-only로 유지한다. 외부 업로드는 하지 않았다.

## Manual Validation Required

설치본과 함께 배포되는 `Manual Validation Required.txt`를 따른다. 특히 구버전에서 clip suspect가 있던 렌더 페이지와 사용자가 이미 문제를 본 표/boxed-table, WMF/EMF 그림, 그림·표 캡션을 확인해야 한다.

오프라인 검증은 인터넷을 끈 상태에서 앱을 완전히 종료·재실행하고 같은 두 문서의 전체 변경 수, 이전/다음 변경, 양쪽 이동·highlight가 동일한지 확인한다. Canvas2D는 설치본 UI에 노출되지 않은 experimental adapter이므로 이번 설치본의 수동 합격 항목이 아니며 자동 PoC 결과만 기록한다.
